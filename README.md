# Dandori

Персональный планировщик на одного пользователя: доска по дням, таймлайн и заметки.
Один адрес на ноутбуке и на телефоне, работает офлайн, ставится на домашний экран.

## Требования

- Node 22+
- Аккаунт Supabase (бесплатного тарифа хватает)
- Аккаунт Cloudflare — только для деплоя

## Supabase

Настройка проекта, схема и политики RLS описаны в [`supabase/README.md`](supabase/README.md).
Пройти по шагам оттуда до того, как запускать приложение.

## Локальный запуск

```sh
cp .env.example .env.local   # подставить URL и anon-ключ из панели Supabase
npm install
npm run dev
```

`.env.local` в репозиторий не попадает: он закрыт `.gitignore`.
Без переменных окружения приложение не стартует и скажет об этом явно.

## Сборка

```sh
npm run build     # проверка типов + сборка в dist/
npm run preview   # локальный просмотр собранного, с рабочим service worker
```

Иконки PWA лежат готовыми файлами в `public/`. Пересобрать их из `public/favicon.svg`
нужно только если менялся сам рисунок:

```sh
npm run icons
```

## Деплой на Cloudflare Pages

1. Запушить репозиторий на GitHub.
2. Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git,
   выбрать репозиторий.
3. Настройки сборки:
   - Framework preset: `None`
   - Build command: `npm run build`
   - Build output directory: `dist`
4. Там же, в разделе **Environment variables (Build)**, добавить для Production
   и Preview:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

   Значения берутся из Supabase → Project Settings → API. В репозитории их нет
   и быть не должно: Vite подставляет их в бандл на этапе сборки, поэтому это
   именно переменные сборки, а не runtime.
5. Save and Deploy. Дальше каждый push в основную ветку деплоится сам.

Переадресация всех путей на `index.html` уже настроена файлом `public/_redirects` —
отдельно в панели ничего указывать не нужно.

После смены переменных окружения нужен повторный деплой (Retry deployment):
старый бандл собран со старыми значениями.

## Установка на телефон

1. Открыть адрес приложения в Chrome на Android (обязательно по HTTPS —
   у Cloudflare Pages он из коробки).
2. Меню браузера → «Установить приложение» (или «Добавить на главный экран»).
3. Запустить с домашнего экрана: адресной строки быть не должно,
   иконка и заставка тёмные, приложение открывается на весь экран.

Если пункта «Установить приложение» нет, значит service worker не зарегистрировался:
проверить, что открыт https-адрес, и обновить страницу.
